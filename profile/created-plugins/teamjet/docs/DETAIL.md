# Заявки TeamJet

Панель в сайдбаре DSH: живой список заявок отеля из TeamJet
(`https://mnzh5.teamjet.com/tasks/general`).

## Что показывает

- счётчики: новые, в работе, принятые, отложенные, срочные;
- таблицу: номер заявки, помещение, суть, статус, остаток до срока, исполнитель;
- поиск по номеру, помещению, тексту и исполнителю; фильтр по статусу;
- автообновление раз в 45 секунд и кнопку «Обновить»;
- срочные заявки поднимаются наверх, затем сортировка по сроку.

## Как устроен доступ к данным

TeamJet авторизует через Keycloak и не отдаёт CORS-заголовки, поэтому браузерная
страница DSH не может обращаться к нему напрямую. Данные идут через локальный мост
`bridge/bridge.mjs`:

```
страница (127.0.0.1:<порт DSH>) → мост (127.0.0.1:8878) → TeamJet API
```

Мост сам выполняет вход и refreshing токена:

| Шаг | Запрос |
|---|---|
| вход | `POST /api/keycloak/login` с `{login, password, hotelkey}` |
| обновление токена | `POST /api/keycloak/refresh` с `refresh_token` |
| список заявок | `POST /api/tasks/v2/list` с `{from,to,status,limit,offset}`, `Authorization: Bearer …` |
| сотрудники | `GET /api/users/list` (id → имя, кеш 5 минут) |

Статусы TeamJet: `1` новая, `2` в работе, `3` выполнена, `4` отложена,
`5` отменена, `6` принята.

Логин и пароль хранятся только в `bridge/bridge.config.json` на этом компьютере
(файл в git не попадает), в браузер они не передаются.

## Ограничения

- API отдаёт максимум 50 заявок за страницу — панель показывает первые 50 по
  выбранному фильтру; полный список с пагинацией смотрите в самом TeamJet.
- Счётчики берутся из `count` того же API и кешируются в мосте на минуту.
- Панель только читает. Смена статусов и комментарии не выведены: это отдельные
  методы API (`/api/tasks/updateStatus`, `/api/tasks/addComment`), у них есть
  побочные эффекты в рабочей системе отеля, поэтому без отдельного решения их не включаю.
- Имена исполнителей подтягиваются из справочника сотрудников; если сотрудник
  уволен и скрыт из справочника, показывается «не назначен».
