# Заявки отеля

Панель в сайдбаре DSH: живой список заявок из CRM «Манжерок 5★»
(`https://mznh5.energycontract.ru`).

## Что показывает

- четыре счётчика: активные заявки, новые, в работе, просроченные по SLA;
- таблицу: номер заявки, комната, суть, приоритет, статус, остаток SLA, исполнитель;
- фильтры по статусу и поиск по номеру, комнате, гостю, исполнителю;
- автообновление раз в 30 секунд (можно выключить) и кнопку «Обновить».

Просроченные заявки всегда поднимаются наверх, затем сортировка по приоритету.

## Как устроен доступ к данным

Страница плагина работает в браузере DSH (`http://127.0.0.1:17198`), а CRM живёт
на другом домене. Браузер заблокировал бы такой запрос правилами CORS, поэтому
данные идут через локальный мост — `bridge/bridge.mjs` в репозитории `dsh-config`:

```
страница (127.0.0.1:17198) → мост (127.0.0.1:8878) → CRM (/api/state)
```

Мост не требует зависимостей, слушает только `127.0.0.1` и отдаёт
`Access-Control-Allow-Origin: *`. Запрос к CRM — публичный `GET /api/state`,
никаких ключей для чтения не нужно.

## Запуск моста

```powershell
cd "$env:USERPROFILE\dsh-config"
node bridge\bridge.mjs
```

Пока мост не запущен, панель показывает подсказку с этой командой вместо данных.

## Ограничения

- Плагин только читает. Создание заявок и смена статусов из моста технически
  возможны (`POST /crm/tasks`, `POST /crm/tasks/:id/status`), но в интерфейсе
  панели пока не выведены: для записи мосту нужен `userId` в
  `bridge/bridge.config.json`.
- SLA (`remainingMs`, `breached`) считает сам CRM на момент запроса; между
  обновлениями панель не пересчитывает остаток по локальным часам.
- Локаль: русский, английский, китайский — берётся из настроек DSH.
